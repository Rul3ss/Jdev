3O primeiro evento: o Button aprende a ouvir cliques

Conceito novo Evento (onClick)

Um evento é algo que a pessoa faz na página: clicar, digitar, passar o mouse.

No React, entregamos uma função para a prop onClick. O React guarda essa função e só chama quando o clique acontece.

<button onClick={() => console.log('clicou!')}>
  clique aqui
</button>

Pense assim: uma campainha: você instala o botão (onClick) e diz o que tocar. Ela só toca quando alguém aperta.

Pense: por que tem () => antes do console.log? (sem a setinha, ele roda na hora que a página abre, e não no clique)

O nosso Button ganha duas props: variante (a cor) e onClick (o que fazer no clique). Ele só repassa o onClick para o <button> de verdade.

Para testar, um botão provisório no Perfil.

Na sua tela
  • Aparece o botão ler mais embaixo do texto "Oi, eu sou...". Abra o Console (F12) e clique: aparece clicou! a cada clique.
Cuidado
  • Se clicou! aparece assim que a página abre, faltou a setinha: onClick={() => ...}.

4useState: o "ler mais" de verdade

Conceito novo useState (estado)

O estado é a memória do componente. O useState devolve duas coisas: o valor atual e a função que troca o valor.

Quando trocamos o valor com essa função, o React desenha o componente de novo com o valor novo.

const [aberto, setAberto] = useState(false)
//      valor   função que troca   valor inicial

Pense assim: um interruptor: aberto diz se a luz está acesa; setAberto é o dedo que aperta o interruptor.

Pense: e se usássemos uma variável comum, let aberto = false? (o valor muda, mas o React não fica sabendo e a tela não muda)

Conceito novo Renderização condicional

Mostrar uma coisa só quando uma condição é verdadeira:

{aberto && <p>{bio}</p>}          // só aparece se aberto for true
{aberto ? 'ler menos' : 'ler mais'}  // escolhe entre dois textos

Pense assim: && é "se sim, mostra"; o ? : é "se sim isto, se não aquilo".

O Perfil agora precisa da bio. Quem entrega é o App.

Na sua tela
  • Clique em ler mais: aparece o segundo parágrafo (a bio) e o botão vira ler menos. Clique de novo: some.
Sua vez

5Curtir: a função atualizadora

Conceito novo Função atualizadora

Quando o valor novo depende do anterior (somar 1), entregamos uma função para o set: ela recebe o valor atual e devolve o novo.

setCurtidas((atual) => atual + 1)

Pense assim: um contador de catraca: cada clique pega o número que está lá e soma 1.

Pense: se eu curtir um projeto, os outros cartões mudam? (não: cada CardProjeto tem a sua própria memória)

Na sua tela

Cuidado
  • Recarregou a página e as curtidas voltaram a 0? É normal: o estado só vive enquanto a página está aberta.

Conceito novo Elevar o estado

Agora queremos um aberto por vez. Mas cada item só conhece a própria memória: um item não sabe que o outro abriu.

A solução é levar o estado para cima, para o pai que os dois têm em comum: o Formacao. O pai guarda qual está aberto e entrega a cada filho duas props: aberto (sim ou não) e onAlternar (função para avisar o clique).

// no pai (Formacao)
const [abertoId, setAbertoId] = useState(null)

<ItemFormacao
  aberto={abertoId === item.id}
  onAlternar={() => alternar(item.id)}
/>

Pense assim: o controle remoto da TV fica com uma pessoa só. Quem quer trocar de canal pede para ela (onAlternar), e ela decide.

Pense: quem guarda a informação agora: o filho ou o pai? (o pai; o filho só mostra e avisa)

No filho, o useState sai. Ele passa a receber aberto e onAlternar pelas props.

No pai, entra o estado com o id do item aberto (null = nenhum).

Na sua tela
  • Só um curso fica aberto: abrir outro fecha o anterior. Clicar no que está aberto fecha ele.
Cuidado
  • Se o clique não faz nada, confira se o pai passou onAlternar e se o filho usa onClick={onAlternar} (sem parênteses).

9Filtro e busca de projetos

Último: filtrar os projetos por tecnologia e buscar pelo nome. Primeiro, tiramos a lista de projetos do App e colocamos num componente só dela. Os dois arquivos são molde: copie.

Na sua tela
  • Nada muda na tela: os mesmos cartões. Só mudamos o código de lugar.

Os botões do filtro. Eles não guardam qual está escolhido: recebem do pai (selecionada) e avisam o clique (onSelecionar). É o mesmo jeito do acordeão: copie.

Conceito novo Estado derivado

A lista filtrada não precisa de useState: ela é calculada a cada desenho, a partir do que já existe (os projetos e a tecnologia escolhida).

Guardamos no estado só o mínimo: a tecnologia escolhida. O resto é conta.

const filtrados = projetos.filter((projeto) => {
  return tecnologia === 'Todas' || projeto.tecnologias.includes(tecnologia)
})

Pense assim: a coluna "total" de uma planilha: ninguém digita o total, ele é uma fórmula.

Pense: o que o .filter devolve? (uma lista nova só com os projetos que responderam true)

Na sua tela
  • Acima dos cartões aparecem os botões Todas, HTML, CSS.... Clique em React: ficam só os projetos com React. Todas volta tudo.
Conceito novo Input controlado

Na busca, o texto do campo fica no estado: value={busca} mostra o estado e onChange guarda cada letra digitada.

Assim o React sempre sabe o que está escrito, e podemos usar a busca no .filter.

<input
  value={busca}
  onChange={(evento) => setBusca(evento.target.value)}
/>

Pense assim: um ditado: a pessoa fala cada letra (onChange) e o React anota no caderno (busca). O campo mostra o que está no caderno.

Na sua tela

  • Digite algo que não existe: aparece Nenhum projeto encontrado e o botão limpar filtros.
Sua vez
