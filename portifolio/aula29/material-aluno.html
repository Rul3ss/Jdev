Do zero: projeto Vite, dados, props e listas

Construir o início do portfólio do zero: criar o projeto, separar os dados do visual e usar props, .map e key para montar a tela.

No final da aula o portfólio terá

  • Projeto React criado com Vite e limpo, com o kit de estilo funcionando.
  • Dados em perfil.js, projetos.js e tecnologias.js.
  • Header, Hero, Footer, Secao, Perfil, Card, Badge, Button e CardProjeto, todos digitados na aula.
  • Um portfólio com Hero, "Quem sou eu" + habilidades e lista de projetos, tudo vindo dos dados.

Antes de começar

  • Este material é para você refazer a aula em casa, no seu ritmo. Siga os passos na ordem: cada um termina com o que deve aparecer na sua tela.
  • Você precisa do Node 20+ e do VS Code instalados. Comece com uma pasta vazia: nada do portfólio existe ainda.
  • A pasta apoio (junto com este arquivo) tem os dois únicos arquivos prontos do curso: estilos.css e Icone.jsx. Os dois vêm comentados: vale ler o topo do estilos.css.
  • A pasta codigo é o projeto completo no fim da aula. Use para comparar com o seu quando algo não funcionar (para rodar: npm install e npm run dev dentro dela).
  • Combinado do curso: ninguém escreve CSS. Só usamos className com os nomes que já existem.
  • No código: linha verde com + é para digitar; vermelha riscada com − é para apagar. Arquivo novo: digite tudo. O botão copiar copia o arquivo inteiro.

2Criar o projeto com Vite e limpar o modelo

Conceito novo Vite e a estrutura do projeto

Vite é a ferramenta que cria o projeto React e abre o site no navegador enquanto programamos.

index.html: a única página. src/main.jsx: o ponto de entrada, que "liga" o React nessa página. src/App.jsx: o componente raiz, de onde tudo vai nascer. package.json: lista de pacotes e comandos (npm run dev).

O modelo vem com uma página de exemplo (logo do React, contador). Vamos apagar o exemplo e deixar só o essencial.

Pense assim: o Vite entrega um caderno com a capa pronta e algumas páginas de exemplo. Arrancamos as páginas de exemplo e começamos o nosso conteúdo.

Terminal
npm create vite@latest portfolio -- --template react
cd portfolio
npm install
npm run dev

Se o terminal perguntar "Install with npm and start now?" ou algo parecido, responda No: nós rodamos npm install na mão. Abra a pasta portfolio no VS Code.

Na sua tela
  • O navegador abre em http://localhost:5173 com a página de exemplo do Vite (logo do React e um botão contador).

Agora limpamos o exemplo. Primeiro apagamos o que não vamos usar:

Apague
  • src/App.css
  • src/index.css
  • src/assets/
  • public/icons.svg

Mantenha public/favicon.svg: é o ícone da aba do navegador.

No index.html, trocamos o idioma para português, o título da aba e carregamos as duas fontes do portfólio.

O visual do portfólio já está pronto em um único arquivo de estilo, e os ícones em um componente. Nesta aula (e no curso todo) ninguém escreve CSS: só usamos os nomes das classes com className.

Arquivo de apoio

src/estilos.css — Kit de estilo: cores, tema claro/escuro e todas as classes (hero, cartao, etiqueta, botao...). Vem comentado: cada variável e cada classe diz o que faz, em quais componentes aparece e o que muda se você trocar o valor.

Copie apoio/estilos.css para src/estilos.css. É um dos dois únicos arquivos prontos do curso: o resto do portfólio é digitado do zero. Abra o arquivo e veja os comentários: O QUE É, ONDE (componentes e aula) e MUDAR (o que acontece se trocar).

Arquivo de apoio

src/components/Icone/Icone.jsx — Componente que desenha os ícones: <Icone nome="seta" />. Vem comentado: cada ícone diz em qual componente é usado.

Copie apoio/Icone.jsx para src/components/Icone/Icone.jsx. É um dos dois únicos arquivos prontos do curso: o resto do portfólio é digitado do zero. Abra o arquivo e veja os comentários: O QUE É, ONDE (componentes e aula) e MUDAR (o que acontece se trocar).

Agora o main.jsx passa a carregar o nosso estilos.css (e não mais o index.css do modelo).

E o App.jsx vira um primeiro teste, com uma frase só.

3Os dados do portfólio: perfil.js e projetos.js

Conceito novo Objeto e lista de objetos

Um objeto é uma ficha: cada linha tem um nome e um valor (nome: 'Maria').

Uma lista (array) guarda vários itens em ordem. Uma lista de objetos é um monte de fichas: perfeito para vários projetos.

Separar os dados do visual é a ideia central do React: o componente só sabe desenhar; o que desenhar vem de fora.

Pense assim: o objeto é a ficha de um aluno; a lista é a pasta com as fichas de todos. O professor muda a ficha, a chamada muda sozinha.

Pense: que informações tem a ficha de vocês?

Crie a pasta src/data. Dentro dela, o arquivo perfil.js: só dados, nenhum JSX.

Sua vez
  • Trocar os dados de Maria Silva pelos seus: nome, cidade, cargo, e-mail e habilidades reais.

Agora a lista de projetos. Digite o primeiro e copie o formato para os outros.

Sua vez
  • Criar pelo menos 4 projetos (podem ser da residência), cada um com id, titulo, descricao, detalhes, tecnologias e repositorio.
Na sua tela
  • Nada muda no navegador: os arquivos ainda não são usados. Sem erro no terminal já está ótimo.

4Header: o primeiro componente com props

Conceito novo Componente

Um componente é uma função que devolve um pedaço de tela (JSX). O nome começa com letra maiúscula e usamos como uma tag: <Header />.

Nosso padrão: uma pasta por componente (components/Header/Header.jsx) e export default.

Pense assim: uma peça de Lego: cada peça faz uma coisa; juntando peças, montamos a tela.

Conceito novo Props

Props são os dados que o componente pai entrega ao filho, como parâmetros de uma função. O filho só lê, nunca altera.

Escrevemos { usuario } na lista de parâmetros para "desembrulhar" a prop (destructuring) e usamos no JSX entre chaves: {usuario}.

<Header usuario="maria" />

function Header({ usuario }) { ... }

Pense assim: uma encomenda com etiqueta: o pai escreve "usuario" na etiqueta, o filho abre e usa.

Pense: podemos usar o mesmo Header em outro portfólio, só mudando a etiqueta? (sim, é o objetivo)

Agora o App importa o Header, importa os dados e entrega o usuario.

Na sua tela
  • Aparece o logo ~/maria_ no topo, com a barra do cabeçalho.
Sua vez
  • Trocar usuario em perfil.js e ver o logo mudar na hora.

5Hero: o cartão de apresentação

O Hero é a primeira coisa que a pessoa vê. Ele recebe quatro props: nome, cargo, resumo e cidade.

É bastante marcação (JSX). Digite com calma (o botão copiar ajuda se cansar): o importante são os {...} que trocam o texto fixo pelos dados.

No App, colocamos o Hero dentro de uma tag <main> e entregamos as 4 props.

Na sua tela
  • Aparece o grande cartão de apresentação com seu nome, cargo, resumo e a janelinha de código à direita.
Cuidado
  • Se aparecer undefined na tela, a prop foi passada com um nome diferente do usado no componente (por exemplo nome e name).

8Secao e Perfil: conteúdo dentro de componentes

Conceito novo children (conteúdo dentro do componente)

Além das props com nome, o componente recebe tudo que está entre a tag de abertura e a de fechamento na prop especial children.

Assim a Secao vira uma "moldura" reaproveitável: serve para qualquer conteúdo.

<Secao>
  <h2>Qualquer coisa aqui</h2>
</Secao>

function Secao({ children }) { ... {children} ... }

Pense assim: um porta-retrato: a moldura é sempre a mesma, a foto dentro muda.

Pense: quantas seções vamos ter? (várias: Sobre, Projetos...) por que não copiar o HTML de cada uma? (repetição)

No App, montamos a seção "Quem sou eu" com a Secao e o Perfil dentro.

Na sua tela
  • Abaixo do Hero surge a seção 01 / sobre com o título "Quem sou eu" e o texto de apresentação.

9Card, Badge e a lista de habilidades

Agora as habilidades viram etiquetas coloridas dentro de um cartão. Precisamos de três coisas: o Card (moldura), o Badge (etiqueta) e uma tabela de cores.

Conceito novo Valor padrão

Se o pai não mandar a prop, o componente usa um valor reserva. Escrevemos assim: cor = 'neutra'. É o jeito do React 19 (no lugar de defaultProps).

Pense assim: o sorvete que sai com granulado por padrão, a menos que você peça outro.

Cada tecnologia deve ter sempre a mesma cor. Em vez de vários if, usamos um objeto como dicionário: a chave é o nome, o valor é a cor.

Conceito novo Lista com .map() e a prop key

.map() percorre uma lista e devolve um item de tela para cada elemento. Em vez de escrever 6 etiquetas, escrevemos 1 molde.

Todo item de uma lista precisa de uma key: um valor único que ajuda o React a saber quem é quem quando a lista muda.

['HTML', 'CSS'].map((tec) => <Badge key={tec} texto={tec} />)

Pense assim: a key é o número da chamada: o professor identifica cada aluno mesmo que a fila mude de ordem.

Pense: o que aconteceria se dois alunos da turma tivessem o mesmo número da chamada?

No App, ao lado do Perfil, entra o cartão de habilidades com um .map.

Na sua tela
  • Ao lado do texto aparece o cartão Habilidades com as etiquetas (HTML e JavaScript em âmbar, CSS em violeta, React em verde-água, as outras em cinza).
Cuidado
  • Esquecer o key gera um aviso vermelho no Console (F12). Vale a pena ver esse aviso uma vez: ele faz parte do aprendizado.

11A prova final e fechamento

Sua vez

  • Trocar a cidade e conferir a janelinha de código do Hero.
  • Abrir o estilos.css, achar --destaque (leia o comentário em cima dele) e trocar o teal #5eead4 por outra cor, como #f472b6. Salvar e ver o que mudou: botões, bolinha do Hero... Depois voltar a cor original.

Isso é "um dado, vários lugares". A tela é consequência dos dados: é o jeito declarativo do React (descrevemos o resultado, o React cuida de atualizar).
